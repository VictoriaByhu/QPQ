# QPQ.Reviews Microservice

Мікросервіс для управління відгуками, розроблений на базі **.NET 8** з суворим дотриманням принципів **Clean Architecture** та патерну **CQRS**.

## 🏗 Архітектура (Clean Architecture)

Проєкт розділений на 4 незалежні шари. Залежності спрямовані виключно всередину (до центру):

1. **Domain (Core):** Ядро системи. Містить сутності (`Review`), Value Objects (`Author`), базові класи та доменні винятки. **Не має жодних зовнішніх залежностей** (включаючи атрибути MongoDB).
2. **Application:** Містить бізнес-логіку системи, розділену на Commands та Queries (CQRS) за допомогою MediatR. Визначає інтерфейси репозиторіїв та містить DTO.
3. **Infrastructure:** Реалізація інфраструктурних деталей. Містить налаштування підключення до MongoDB, репозиторії, BSON-мапінг (`BsonClassMap`), автоматичне створення індексів та Data Seeding.
4. **WebApi:** Точка входу в застосунок. Містить API-контролери, глобальний обробник помилок (Exception Middleware) та налаштування Swagger.

## ✨ Основні реалізовані можливості

* ✅ **CQRS:** Розділення операцій запису (через `IReviewRepository`) та читання (через `IReviewQueries` із прямою проєкцією бази даних у DTO).
* ✅ **MediatR Pipeline Behaviors:** 
  * `LoggingBehavior`: Логування початку та завершення кожного запиту.
  * `ValidationBehavior`: Автоматична валідація запитів через FluentValidation до виконання бізнес-логіки.
  * `PerformanceBehavior`: Відстеження запитів, що виконуються довше 500 мс.
* ✅ **Exception Handling (ProblemDetails):** Централізований `ExceptionMiddleware`, який перехоплює доменні винятки, помилки валідації та конфлікти бази даних, повертаючи стандартизовані відповіді з правильними HTTP-статусами (400, 404, 409, 500).
* ✅ **Оптимістична конкурентність:** Захист від конфліктів при одночасному редагуванні відгуку на основі поля `Version`.
* ✅ **MongoDB Integration:** 
  * Збереження Value Object (`Author`) як вкладеного документа.
  * Автоматичне наповнення бази тестовими даними при старті (Data Seeding).
  * Автоматична розбудова індексів (складений індекс сортування та текстовий індекс для повнотекстового пошуку).

## 🚀 Як запустити локально

1. Переконайтеся, що у вас встановлено та запущено локальний сервер **MongoDB** (за замовчуванням `mongodb://localhost:27017`).
2. Відкрийте рішення у Visual Studio або виконайте команду `dotnet build`.
3. Запустіть проєкт `QPQ.Reviews.WebApi` (натисніть `F5` у Visual Studio).
4. Застосунок автоматично створить базу даних `QPQ_ReviewsDb`, налаштує необхідні індекси, додасть початкові тестові документи та відкриє сторінку **Swagger UI** у браузері для тестування API.
