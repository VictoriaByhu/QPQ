# Контексти піддомену Swaps

Піддомен Swaps складається з трьох незалежних контекстів. Кожен має власний API та власну базу. Між базами немає спільних таблиць, JOIN і FOREIGN KEY: контексти обмінюються лише ідентифікаторами та подіями. Кожна сутність належить рівно одному контексту, локальні копії чужих даних позначені нижче.

## Огляд

| Контекст | Відповідальність | Сховище | База |
|---|---|---|---|
| Swaps | обмін: учасники, навички, статус, історія змін | SQL Server, ADO.NET + Dapper | `QPQ_Swaps` |
| Sessions | зустрічі в межах прийнятого обміну | SQL Server, EF Core | `QPQ_Sessions` |
| Messages | листування учасників обміну | MongoDB | `QPQ_Messages` |

## Swaps

| Питання | Відповідь |
|---|---|
| Власні сутності | Swap, SwapDetails, SwapSkill, SwapStatusHistory |
| Копії чужих даних | `Skills` (`Id`, `Name`) з Catalog |
| Посилання на користувачів | `InitiatorId`, `PartnerId`, `CreatedBy`, `UpdatedBy`, `ChangedByUserId` (лише `UserId` з Identity) |
| Подія, яку видає | `SwapAccepted`, `SwapCompleted` |
| Подія, яку обробляє | `SkillChanged` (оновлення копії навичок), `UserDeleted` |
| Чому такий вибір сховища | жорстка схема, транзакційна зміна статусу, збережувані процедури та оптимістична конкурентність |

## Sessions

| Питання | Відповідь |
|---|---|
| Власні сутності | Session, SessionSkill, SessionOutcome, SessionFormat (довідник) |
| Копії чужих даних | `AcceptedSwaps` (`SwapId`, `InitiatorId`, `PartnerId`, `Status`) зі Swaps; `Skills` (`Id`, `Name`) з Catalog |
| Посилання на користувачів | `CreatedByUserId`, а також `InitiatorId` і `PartnerId` у копії обміну |
| Подія, яку видає | немає |
| Подія, яку обробляє | `SwapAccepted` (дозволяє створювати зустрічі), `SwapCompleted` (оновлює статус копії), `SkillChanged` |
| Чому такий вибір сховища | розвинена реляційна модель (1:1, 1:N, M:N з власним полем, довідник); запити та міграції зручно вести через EF Core |

## Messages

| Питання | Відповідь |
|---|---|
| Власні сутності | conversations, messages, attachments |
| Копії чужих даних | `conversations`: `swapId`, `swapStatus`, `participants` (`userId`, `role`) зі Swaps |
| Посилання на користувачів | `senderId`, `uploadedBy`, `participants.userId` |
| Подія, яку видає | немає |
| Подія, яку обробляє | `SwapAccepted` (створює розмову та системне повідомлення), `SwapCompleted` (оновлює `swapStatus`) |
| Чому такий вибір сховища | повідомлення різних типів мають різні набори полів, учасники та вкладення природно вбудовуються в документи, багато записів із читанням за розмовою в хронологічному порядку |

## Правила доступу

- Права перевіряються за токеном: учасник обміну бачить лише свої Sessions і Messages.
- Персональні дані (ім'я, email, аватар) живуть тільки в Identity, у доменних базах зберігається лише `UserId`.
