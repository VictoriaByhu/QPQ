# Система управління спільнотою: Репутація, Відгуки та Модерація

## 1. Опис предметної області
Система призначена для управління взаємодією користувачів на платформі (наприклад, маркетплейсі або форумі). Вона дозволяє користувачам залишати відгуки на товари/послуги, здобувати репутаційні бали та досягнення за активність, а також містить ізольовану підсистему модерації для обробки скарг на недобросовісних користувачів. Система побудована за мікросервісною архітектурою (Database-per-Service).

## 2. Межі контекстів (Bounded Contexts)
Систему розділено на 3 незалежні контексти. Жодних спільних таблиць та жодного зовнішнього ключа (FOREIGN KEY) між базами немає — зв'язок відбувається виключно за ідентифікаторами.

1. **Контекст «Модерація» (Проєкт №1 — SQL Server + ADO.NET/Dapper)**
   - Відповідальність: Обробка скарг (репортів) на користувачів, призначення модераторів, транзакційна зміна статусів розгляду.
   - Сутності: Moderators, Reports, ReportDetails, ViolationTypes, ReportViolations.

2. **Контекст «Репутація» (Проєкт №2 — SQL Server + EF Core)**
   - Відповідальність: Гейміфікація профілів користувачів, нарахування балів, видача бейджів та призначення рівнів довіри.
   - Сутності: ReputationProfile, ProfileSettings, TrustLevel, Badge, UserBadge.

3. **Контекст «Відгуки та Обговорення» (Проєкт №3 — MongoDB)**
   - Відповідальність: Зберігання відгуків з динамічною структурою (фотографії, вкладені коментарі), рейтинги та обговорення.
   - Колекції: reviews, discussions, product_ratings.

## 3. Політика дублювання даних та узгодженості
Щоб уникнути синхронних міжсервісних викликів (JOIN) при кожному читанні, ми застосовуємо дублювання даних.

| Поле, що дублюється | Де зберігається (БД) | Джерело (Власник даних) | Політика узгодженості |
| :--- | :--- | :--- | :--- |
| `Reports.TargetUserId` | БД Модерації (SQL) | БД Користувачів (Ідентифікація) | Незмінний ідентифікатор. |
| `Reports.TargetUserDisplayName` | БД Модерації (SQL) | БД Користувачів (Ідентифікація) | **Знімок (Snapshot):** фіксується на момент створення скарги. Не оновлюється. |
| `ReputationProfile.UserId` | БД Репутації (SQL) | БД Користувачів (Ідентифікація) | Незмінний ідентифікатор. |
| `reviews.productName` | БД Відгуків (MongoDB) | БД Каталогу товарів | **Локальна копія:** оновлюється асинхронно через події при зміні назви товару. |
| `reviews.author.displayName`| БД Відгуків (MongoDB) | БД Користувачів (Ідентифікація) | **Локальна копія:** оновлюється подіями від сервісу користувачів. |

## 4. Порядок розгортання баз даних з нуля

### Проєкт №1 (Модерація)
База створюється через виконання "чистих" SQL-скриптів у SQL Server Management Studio (SSMS).
1. Створіть порожню базу даних: `CREATE DATABASE QPQ_Moderation;`
2. Виконайте скрипт `schema.sql` (створення таблиць, індексів, обмежень та аудитних колонок).
3. Виконайте скрипт `procedures.sql` (створення 4 збережуваних процедур).
4. Виконайте ідемпотентний скрипт `seed.sql` (наповнення початковими даними).

### Проєкт №2 (Репутація)
База керується через міграції Entity Framework Core.
1. Відкрийте рішення у Visual Studio.
2. Перевірте, що у файлі `appsettings.json` вказано правильний сервер.
3. Відкрийте Package Manager Console, переконайтеся, що вибрано проєкт `QPQ.Reputation`.
4. Виконайте команду: `Update-Database`.

### Проєкт №3 (Відгуки)
База NoSQL розгортається у MongoDB.
1. Запустіть локальний сервер MongoDB та відкрийте MongoDB Shell (mongosh) або Compass.
2. Створіть/виберіть базу даних: `use qpq_reviews`.
3. Виконайте скрипт `mongo-init.js`.
